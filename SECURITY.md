# Security and update policy

- **Isolation:** Unchanged from the source project: rootless Podman, no host sockets/home mounts, capability drop and `no-new-privileges`. `usb` exposes one device; `nested` relaxes seccomp. Networking is enabled and may reach the LAN. A VM is safer for high-risk programs.
- **Base:** `docker.io/library/debian:sid` (the official Debian unstable image). Fresh uncached builds run `apt-get update` with error-mode checks, `apt-get full-upgrade`, install only requested tools plus dependencies, and reject any still-pending apt upgrades. Sid is a rolling, unstable distribution: temporary package transitions can break a build.
- **Preinstalled toolchains:** All profiles retain the original Node.js, Python, Rust and Go CLI command set plus basic compilers. Debian sid packages the system tools. The original `uv` CLI is installed in an isolated global pipx environment because Debian sid packages only `python3-uv-build`, not uv itself. This contacts PyPI at build time; Trivy scans the resulting image as a whole. No other nonessential language runtime has been added.
- **Fish source:** Fish comes exclusively from the official Debian sid package repository. It is upgraded with the other Debian packages; no separate source or fish-specific version pin is used.
- **Cadence:** The GHCR workflow runs approximately every three days, plus pushes and manual runs. GitHub cron uses days 1, 4, 7, ... of each month, not an exact 72-hour cadence; scheduled jobs may be delayed or suspended for inactivity.
- **CI tool maintenance:** Dependabot updates SHA-pinned GitHub Actions weekly. ShellCheck follows the hosted runner; a separate weekly check opens GitHub issues for newer stable Trivy and actionlint releases. Workflow version pins require maintainer review.
- **Gate:** Debian sid does not use a separate stable-style security pocket/advisory feed; a clean apt upgrade state is a package-freshness check, **not** a security-advisory audit. Trivy scans candidate digests on amd64 and arm64; any scanner error or **fixable HIGH/CRITICAL** CVE blocks `latest`/version tag promotion, except for one runtime-verified, exact-match pip SBOM false positive (`setuptools 70.3.0`, `CVE-2025-47273`). The original JSON findings are retained; no other CVE or actual vulnerable installation is ignored. The exception is evaluated afresh with the pinned Trivy on each run (including every-third-day scheduled runs) and becomes inactive as soon as that false finding disappears; newer Trivy releases are flagged weekly for maintainer review. **Unfixed** vulnerabilities, newly published issues without fixes, and false negatives can remain. Failed runs retain the previously published image. The unique candidate tag can remain publicly accessible.
- **Traceability:** The workflow creates Buildx multi-architecture SBOM metadata, two full SPDX JSON SBOM artifacts, GitHub provenance and SBOM attestations, and a Cosign keyless signature on the multi-architecture image digest. Verify signatures against the repository's *specific workflow identity*, not only the registry address.
- **Rollout:** GHCR does not automatically patch running Podman containers. Pull a new image and recreate each container; retain your named `/work` volume as needed. Production users should pin a verified digest and update deliberately.
- **GHCR retention:** A daily cleanup deletes versions older than seven days, while preserving `latest` and skipping cleanup if that image is stale or missing. Old release tags, candidate images, digests and GHCR-resident signatures/attestations can become unavailable after cleanup. Retain required artifacts elsewhere before relying on long-lived digest pins. Manual cleanup previews deletions by default.
- **Operational controls:** Protect workflow changes and release tags with appropriate GitHub repository permissions. If `GITHUB_TOKEN` lacks package write permission, grant the repository permission on existing GHCR packages. GitHub Artifact Attestations in private repositories require eligible plans.
- **Reporting:** Use GitHub's private vulnerability reporting feature, when enabled, or contact the maintainer privately. Keep Debian and uv license notices intact; see `THIRD_PARTY_NOTICES.md`.
